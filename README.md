## 🌾 1. Project Overview & Architecture

This project implements an end-to-end Big Data analytics framework designed to analyze structured market arrival prices, meteorological rainfall patterns, unstructured farmer advisory discussions, and semi-structured crop metadata using the **Apache Hadoop Ecosystem**.

### System Architecture Flow:
$$\text{MySQL (Mandi Prices)} \xrightarrow{\text{Apache Sqoop (-P)}} \text{HDFS} \xrightarrow{} \begin{cases} \text{Apache Hive} & (\text{Structured Mandi Price Analytics}) \\ \text{Apache Pig} & (\text{Unstructured Text \& Rainfall Dataflows}) \\ \text{MongoDB} & (\text{Semi-structured Crop Metadata Documents}) \end{cases}$$

```
+----------------------------------------------------------------------------------------------------+
|                                    HADOOP ECOSYSTEM PIPELINE                                       |
+----------------------------------------------------------------------------------------------------+
|  [data/mandi_prices.csv]    ---> MySQL (mandi_prices) ---> Sqoop incremental ---> HDFS ---> Hive |
|  [data/rainfall_india.csv]  ---> HDFS (/agri/rainfall) --------------> Apache Pig (rainfall.pig)  |
|  [data/farmer_queries.csv]  ---> HDFS (/agri/queries)  --------------> Apache Pig (keywords.pig)  |
|  [data/crop_production.csv] ---> Node.js (csv-parser)  --------------> MongoDB (agri_db)          |
|                                                                                                    |
|  Hive & Pig Analytics       ---> export_results.sh     --------------> dashboard/data/*.json       |
|  MongoDB Aggregation        ---> mongo_import.js       --------------> yearly production JSON      |
|  Yearly forecast            ---> predict.py            --------------> forecast.json               |
|                                                                                |                   |
|                                                                                v                   |
|                                                                     Responsive Web Dashboard       |
+----------------------------------------------------------------------------------------------------+
```

## 🗺️ 3. Rainfall SUBDIVISION Mapping & State + Month Relational Join

### The Challenge:
Meteorological rainfall is reported by **IMD Meteorological Subdivisions** (e.g. `PUNJAB`, `COASTAL ANDHRA PRADESH`, `MADHYA MAHARASHTRA`, `MARATHWADA`, `VIDARBHA`, `KONKAN & GOA`, `WEST UTTAR PRADESH`), whereas Mandi price records are recorded by administrative **State** (`Punjab`, `Andhra Pradesh`, `Maharashtra`, etc.) and arrival **Date**.

### The Solution:
1. **Pig Latin Mapping (`scripts/rainfall.pig`)**:
   IMD subdivisions are mapped to canonical administrative state names:
   ```pig
   mapped_rainfall = FOREACH clean_rainfall GENERATE
       (CASE 
           WHEN (UPPER(subdivision) MATCHES '.*MAHARASHTRA.*' OR 
                 UPPER(subdivision) MATCHES '.*MARATHWADA.*' OR 
                 UPPER(subdivision) MATCHES '.*VIDARBHA.*' OR 
                 UPPER(subdivision) MATCHES '.*KONKAN.*') THEN 'Maharashtra'
           WHEN (UPPER(subdivision) MATCHES '.*ANDHRA.*' OR 
                 UPPER(subdivision) MATCHES '.*RAYALSEEMA.*') THEN 'Andhra Pradesh'
           WHEN UPPER(subdivision) MATCHES '.*PUNJAB.*' THEN 'Punjab'
           WHEN UPPER(subdivision) MATCHES '.*UTTAR PRADESH.*' THEN 'Uttar Pradesh'
           WHEN UPPER(subdivision) MATCHES '.*TAMIL NADU.*' THEN 'Tamil Nadu'
           WHEN UPPER(subdivision) MATCHES '.*HARYANA.*' THEN 'Haryana'
           WHEN UPPER(subdivision) MATCHES '.*GUJARAT.*' THEN 'Gujarat'
           WHEN UPPER(subdivision) MATCHES '.*KARNATAKA.*' THEN 'Karnataka'
           ELSE subdivision
       END) AS state:chararray, ...;
   ```
2. **Hive Relational Join (`scripts/analysis.hql` - Query 5)**:
   Mandi prices and monthly rainfall averages are joined on **`state + month`**:
   ```sql
   SELECT 
       m.state,
       r.month_name,
       ROUND(r.avg_rainfall, 1) AS rainfall_mm,
       ROUND(AVG(m.modal_price), 2) AS avg_mandi_price
   FROM hive_mandi_prices m
   JOIN hive_monthly_rainfall r 
     ON (LOWER(TRIM(m.state)) = LOWER(TRIM(r.state)) 
         AND CAST(SUBSTR(m.arrival_date, 6, 2) AS INT) = r.month_num)
   GROUP BY m.state, r.month_name, r.month_num, r.avg_rainfall
   ORDER BY r.month_num ASC;
   ```

## ⚙️ 4. Execution Order & Refresh Schedule (WSL Ubuntu)

Run the Hadoop, Hive, Pig, MySQL, and MongoDB commands inside WSL Ubuntu (`wsl -d Ubuntu`).

### One-time initialization

Start the required services and daemons:

```bash
sudo service ssh start
start-dfs.sh
start-yarn.sh
sudo service mysql start
sudo systemctl start mongod || sudo service mongodb start
```

Set up the MySQL table once, then create HDFS folders and upload the rainfall and farmer-query source files:

```bash
cd /path/to/agri-bigdata-project/scripts
mysql -u root -p < mysql_setup.sql
bash hdfs_setup.sh
npm install
python3 -m pip install -r requirements.txt
```

### Expand mandi coverage from data.gov.in

To import an already downloaded authentic mandi CSV, validate it and merge it with the existing source without replacing existing records:

```bash
cd /path/to/agri-bigdata-project/scripts
python3 fetch_mandi_prices.py --input /path/to/downloaded-mandi.csv
mysql --local-infile=1 -u root -p < mysql_import_mandi_updates.sql
bash refresh_pipeline.sh
```

To download additional records directly, create a data.gov.in API key and enter it only into the local shell environment. The downloader reads the project’s exported state list, validates all responses, merges duplicate market/date entries, and replaces `data/mandi_prices.csv` only after every state request succeeds. A failed or empty download leaves the current CSV untouched.

```bash
cd /path/to/agri-bigdata-project/scripts
read -rsp "data.gov.in API key: " DATA_GOV_IN_API_KEY
export DATA_GOV_IN_API_KEY
echo
python3 fetch_mandi_prices.py
unset DATA_GOV_IN_API_KEY
mysql --local-infile=1 -u root -p < mysql_import_mandi_updates.sql
bash refresh_pipeline.sh
```

Do not rerun `mysql_setup.sql` to add downloaded rows: it drops and recreates the MySQL table. The update import stages the merged CSV and inserts only market/date records not already in MySQL; `refresh_pipeline.sh` then imports their new IDs and rebuilds dashboard exports.

Do not rerun `mysql_setup.sql` during a refresh: it recreates the table and resets its generated `record_id` values. On the first `refresh_pipeline.sh` run, Sqoop imports from the initial `record_id` checkpoint. Later runs append only newer IDs and persist the checkpoint in `scripts/.sqoop_last_record_id`.

```bash
bash refresh_pipeline.sh
```

The refresh runs incremental Sqoop, both Pig workflows, Hive partition refresh and analytics, JSON export, MongoDB aggregation, and `predict.py`. Hive rebuilds year/month partitions from the accumulated HDFS import. The dashboard timestamp is written by `export_results.sh` after successful Hive exports.

### Schedule refreshes

For an unattended cron job, configure Sqoop to read a protected password file stored in HDFS, then set `SQOOP_PASSWORD_FILE` to that HDFS path in the cron environment. Without it Sqoop prompts securely using `-P`, which is suitable for manual execution but not cron.

Example (adjust the project path and schedule for the deployment):

```cron
*/30 * * * * cd /path/to/agri-bigdata-project/scripts && SQOOP_PASSWORD_FILE=/user/your-user/.mysql-sqoop-password bash refresh_pipeline.sh >> /path/to/agri-refresh.log 2>&1
```

Run the dashboard web server from the project root:

```bash
cd ../dashboard
python3 -m http.server 8080
```

Open **`http://localhost:8080`**. Missing generated JSON is shown as an empty state; run a successful refresh to populate the outputs.

## ⚠️ Limitations

- Price forecasting is disabled when mandi data covers fewer than twelve distinct months. The dashboard reports the real distinct-date count and uses the rainfall-versus-price comparison instead. The currently checked-in mandi file contains one distinct date/month; coverage is recalculated from the source file on each forecast run.
- Rainfall is reported by IMD meteorological subdivision and mapped many-to-one to administrative states. State rainfall comparisons are approximate and are not district-level measurements.
- Production forecasts are estimates from the available historical state/crop/season series; sparse series may not have enough observations for holdout metrics or forecasts. Results are not guaranteed.

## 🔍 5. How to Verify (CAT–II Evaluation Metrics)

Use the commands below to collect proof for your project report evaluation metrics:

### Metric 1: Data Integrity (MySQL vs. HDFS Row Count Parity)
Verify that the record count transferred from MySQL via Sqoop matches HDFS exactly:

```bash
# 1. Count records in MySQL:
mysql -u root -p -e "USE agri_db; SELECT COUNT(*) AS mysql_row_count FROM mandi_prices;"

# 2. Count records in HDFS:
hdfs dfs -cat /agri/mandi/part* | wc -l
```
*Verification standard:* Both counts must match, proving zero data loss during Sqoop bulk transfer.
